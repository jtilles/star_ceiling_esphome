Connection

Not specified in manual — 9600 is the common default for these RS232 controllers. Change and reconnect if the panel doesn't respond.
Defaults are the standard HM-10 UUIDs (FFE0 service / FFE1 characteristic, used for both write and notify). Many clone modules (CC41-A, AT-09, etc.) reuse these — if pairing connects but nothing happens, check your module's datasheet or scan it with a BLE explorer app to confirm the real UUIDs, then edit the fields above and reconnect.

Protocol Notes star_zone firmware

New commands live under a leading !, which can never collide with the original grammar (single letters, and comma-delimited strings starting with c A D d X Y Z e k n, terminated by *) — see firmware/star_zone/README.md's command grammar table. This console targets the real, implemented star_zone firmware for the Top-Star/Bot-Star zone chips specifically (each chip drives its own independent 8-LED strip) — not the original Illuminate Enhanced PRD's abandoned single-merged-MCU design, so a few PRD-only ideas that never got built (multiple concurrent streaks per shooting-star zone, per-effect speed codes, custom palette definitions, Perlin-noise ambient, identify output/count/dwell, per-zone/min-max-variance meteor showers) have been dropped below rather than left sending commands the firmware doesn't understand. (Custom shooting-star trail length, once on that dropped list, was later actually implemented as !L — see the Shooting Star — Trail & Speed panel below.)

Shooting Star

Now functional via the star_zone replacement firmware (stock chips have no Shooting Star support at all) — X/Y/Z are 3 independent, concurrent streak slots sharing this chip's own 16-LED strip, not a separate physical output. The last field is an interval in seconds, not a duration: it fires one streak now, then another every N seconds, indefinitely, until turned off - it does not run continuously for N seconds.
1 / 2 / 10 are included so the same wire byte can also test the legacy Illuminate 1.0 ShootingStarDuration enum {0,1,2,5,10} minutes against real SS-firmware hardware — star_zone reads this byte as seconds, SS-firmware reads it as one of five duration steps. Meteor Shower — Auto Mode New

An extra, automatic streak generator layered on top of everything else - it does not use the X/Y/Z zones above (it has its own slot) and needs no color picked: each shot uses whatever color the Palette-Driven Twinkle panel has selected, or the current Starry Night color if no palette is active. Its timing is randomly jittered around the average interval below (not exactly periodic like the X/Y/Z zones), so it reads as organic background sparkle rather than a predictable per-zone shot.

Identify / Install Mode New

Palette-Driven Twinkle New

Twinkle/Firefly/Breeze/Rain Drops/Jamboree can draw from one of the firmware's built-in palettes instead of one fixed color (no custom palette definitions - built-ins only). Rainbow Cycle is special: every LED holds the same hue at the same time and the whole strip fades smoothly through the spectrum together, paced by Effect Speed (60s per full sweep at speed 0, 2s at 255). That's different from the gold Rainbow transition, which spreads hues across the strip instead.

Raw Command

Sent exactly as typed — no character is appended automatically. Doubles as the "raw passthrough / escape hatch" called out in the PRD for exercising firmware commands before they're modeled as first-class controls above.

Diagnostics New

Regression tests for the serial parser's "resync on stray command-start byte" logic (protocol.cpp's poll()) — this exact class of bug caused a real incident where a misparsed command fired a shooting star for ~4 hours. Each button below sends one raw write with no separator between the fragments, to exercise the byte-stream parser directly rather than one full command at a time.
Expected: only D,50* (star dim → 50%) takes effect; the incomplete c,1,2 fragment is silently dropped, not corrupt-parsed.
The other historically-real bug — resync incorrectly firing inside a !-prefixed command when a field's letter value (e.g. zone X/Y/Z) collides with a legacy command-start byte — is already exercised by the Shooting Star — Trail & Speed panel above whenever zone X is selected (its wire command is !L,X,...*, and X is itself a legacy command-start byte). No separate control needed here; just include that panel with zone X selected in any regression pass.

Requires Chrome, Edge, or another browser supporting Web Serial (wired RS232) and Web Bluetooth (wireless BLE). Web Bluetooth additionally requires HTTPS or localhost. Gold controls are drawn directly from the Illuminate 1.0 RS232 reference (unchanged, sent to the stock Main/RGBW chips or the star_zone firmware's backward-compatible parser alike); teal controls send the !-prefixed enhancement commands implemented in firmware/star_zone/ — see that project's README for the full grammar and any chip-specific caveats (e.g. reception reliability) before relying on them.
